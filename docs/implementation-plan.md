# 実装計画

## 前提

本計画はMVPを小さな順序付きフェーズで実装するための基準である。各フェーズは原則として前フェーズの完了条件を満たしてから開始する。現時点では文書作成のみを行い、以下の実装は行わない。

## 1. プロジェクト初期化

- **目的:** 確定技術スタックで最小の開発・ビルド環境を用意する。
- **作業内容:** 依存関係をインストールする前に、リポジトリ直下へ `[install]` と `minimumReleaseAge = 604800` を設定した `bunfig.toml` を作成する。Next.js、TypeScript、App Router、Tailwind CSSをBunで初期化し、Bunだけで依存パッケージをインストールする。直接依存と新しく解決される間接依存の両方に7日間の最低公開期間を適用し、依存関係を `bun.lock` に統一する。不要なテンプレートを整理し、`package-lock.json`、`pnpm-lock.yaml`、`yarn.lock` が存在しないことを確認する。GitHubリポジトリと基本的なVercel互換設定を確認する。
- **完了条件:** `bunfig.toml` の `minimumReleaseAge` が604800で、`minimumReleaseAgeExcludes` が設定されていない。`bun.lock` が生成され、他のパッケージマネージャーのロックファイルが存在しない。`bun run lint` と `bun run build` が成功し、`bun dev` で初期ページを表示できる。
- **依存関係:** 本仕様書一式、BunとNext.jsの対応バージョン確認。
- **今回含めない内容:** ページ実装、コンテンツ、音声、デプロイ。

## 2. 型定義と静的データ

- **目的:** 5問題とフレーズを型安全に追加・参照できる基盤を作る。
- **作業内容:** `Phrase`、`Problem` 型、静的データ配置、slug検索方法を実装する。確定した5問題データを追加する。
- **完了条件:** 5問題が型検査を通り、各問題に3〜5件のフレーズがあり、slug・ID・音声パスの規則に一致する。
- **依存関係:** フェーズ1、`docs/content-spec.md`、人間が確認した実コンテンツ。
- **今回含めない内容:** UI、音声ファイル生成、API、DB。

## 3. 共通コンポーネント

- **目的:** 3画面で必要な最小限の一貫したUI部品を用意する。
- **作業内容:** ページコンテナ、文字付きボタン／リンク、問題カード、フレーズカードのうち共有価値が明確なものを実装する。
- **完了条件:** 375px前後で読みやすく、キーボード操作、フォーカス、コントラストの基本要件を満たす。
- **依存関係:** フェーズ1〜2、`docs/screen-spec.md`。
- **今回含めない内容:** 汎用デザインシステム、外部UIライブラリ、モーダル、音声ロジック。

## 4. トップページ

- **目的:** サービスの用途と制約を伝え、問題一覧へ案内する。
- **作業内容:** サービス名、短い説明、`Choose your problem`、ログイン不要の説明、緊急サービスではない旨を表示する。
- **完了条件:** `/` が仕様項目を表示し、主ボタンから `/problems` へ移動できる。
- **依存関係:** フェーズ3、トップページの未確定英語文言の確定。
- **今回含めない内容:** 認証、検索、カテゴリ選択、追加CTA。

## 5. 問題一覧

- **目的:** 利用者が5つの困りごとから1つを選べるようにする。
- **作業内容:** 見出し `What problem are you having?` と、静的データに基づく5カードを表示する。
- **完了条件:** `/problems` に5件だけ表示され、各カードが正しい詳細URLへ移動する。
- **依存関係:** フェーズ2〜3。
- **今回含めない内容:** 検索、絞り込み、並べ替え、追加カテゴリ。

## 6. 問題詳細

- **目的:** 選んだ状況と解決用フレーズを提示する。
- **作業内容:** 戻る操作、問題名、状況説明、3〜5件のフレーズカードを実装し、静的生成対象slugと404処理を設定する。
- **完了条件:** 全有効slugで正しい内容を表示し、無効slugは404となる。各カードで日本語が最も目立つ。
- **依存関係:** フェーズ2〜3、5問題分の確定コンテンツ。
- **今回含めない内容:** モーダル挙動、実音声、実行時データ取得。

## 7. 全画面表示モーダル

- **目的:** 利用者が選んだ日本語を駅員へ大きく見せられるようにする。
- **作業内容:** `Show to staff` から開くモーダル、大きな日本語、小さな英訳、音声ボタン、閉じる操作、フォーカス管理を実装する。
- **完了条件:** タッチとキーボードで開閉でき、背面操作を防ぎ、閉じた後に起点へフォーカスが戻る。
- **依存関係:** フェーズ6、`staffMessage` と個別フレーズの表示関係、閉じ方の未確定事項の解消。
- **今回含めない内容:** 独立ルート、共有機能、複雑なアニメーション。

## 8. 音声ファイル追加

- **目的:** 利用時のAPIなしで、各日本語フレーズを再生できるようにする。
- **作業内容:** TTSサービスを選定し、確認済み日本語からMP3を一度生成する。命名規則に従って `public/audio/train/` に置き、再生・失敗表示を実装する。
- **完了条件:** 全音声パスが実在し、対応文を明瞭に再生し、再生不能時にも文字情報と英語エラーを表示できる。
- **依存関係:** フェーズ2、6〜7、TTSサービス・話者・速度の決定、人間による音声確認。
- **今回含めない内容:** 実行時TTS API、録音、発音判定、音声編集機能。

## 9. 動作確認

- **目的:** 機能、レスポンシブ表示、アクセシビリティ、ビルド品質を確認する。
- **作業内容:** 受け入れ条件を全ルート・全問題で確認し、375px前後、キーボード、音声成功・失敗、404を試験する。`bun run lint` と `bun run build` を実行する。
- **完了条件:** `docs/screen-spec.md` の受け入れ条件を満たし、lint・buildが成功し、重大な操作不能や表示崩れがない。
- **依存関係:** フェーズ1〜8。
- **今回含めない内容:** 大規模な自動テスト基盤、性能監視サービス、仕様外端末の網羅。

## 10. GitHubとVercelへのデプロイ

- **目的:** 確認済みMVPを追跡可能な状態で公開する。
- **作業内容:** 変更をGitHubへコミット・プッシュし、Vercelプロジェクトを接続して本番デプロイする。
- **完了条件:** GitHubの対象コミットとVercel本番URLが対応し、3ルート、静的アセット、MP3をHTTPSで利用できる。
- **依存関係:** フェーズ9、GitHub・Vercelのアカウントと公開範囲の決定。
- **今回含めない内容:** AWS、Docker、独自バックエンド、複雑なCI/CD。

## 11. 実機確認

- **目的:** 実際のスマートフォンと駅に近い利用条件で使いやすさを確認する。
- **作業内容:** 375px前後を含む実機で、屋外の明るさ、通信状況、端末音量、タップ、文字提示を確認する。
- **完了条件:** 必要なフレーズへ迷わず到達し、日本語提示と音声が実用的で、重大なレイアウト・操作問題がない。
- **依存関係:** フェーズ10、確認対象端末と実施者の確保。
- **今回含めない内容:** 全機種網羅、ネイティブアプリ、オフライン対応。

## 12. ユーザー価値の検証

- **目的:** 機能の存在ではなく、旅行者の問題解決に役立つかを確認する。
- **作業内容:** 対象ユーザーに基本フローを試してもらい、到達率、操作数、時間、迷い、使った提示方法、不足コンテンツを記録する。
- **完了条件:** `docs/product-spec.md` の指標について結果が記録され、継続・修正・停止の判断材料と次の最小改善が明確になる。
- **依存関係:** フェーズ11、検証協力者、計測方法と目標値の決定。
- **今回含めない内容:** 仕様外機能の即時追加、大規模分析基盤、利用者向けリアルタイムAI。
