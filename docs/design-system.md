# デザインシステム

## この文書の責務

本書は、現在の電車・駅カテゴリと将来追加される可能性があるカテゴリに共通する、視覚・操作デザインの方針を定義する。画面固有の項目と遷移は `docs/screen-spec.md`、プロダクト範囲は `docs/product-spec.md` を参照する。

## 1. デザインの目的

日本旅行中に困っている外国人が、焦っている状況でも迷わず使えることを最優先にする。UIは次の特徴を持つ。

- Simple
- Calm
- Reliable
- Practical
- Mobile-first
- Accessible
- Easy to scan

観光情報サイト、日本語教材、鉄道会社の公式サイトのような見た目ではなく、旅行中の問題解決に使う実用ツールとして設計する。現在の電車・駅カテゴリだけに最適化せず、飲食店、ホテル、買い物、病院・体調不良、観光施設などへ展開できる共通性を保つ。

## 2. デザインの基本原則

- 装飾より可読性を優先する。
- 1画面に情報を詰め込みすぎない。
- 次に行う操作を明確にする。
- 主要操作の位置と見た目を画面間で統一する。
- 色だけで状態やカテゴリを表現しない。
- アイコンには必ず文字ラベルを併記する。
- 375px前後のスマートフォンを基準にする。
- 片手で操作しやすいタップ領域を確保する。
- 屋外利用を想定し、文字と背景の十分なコントラストを確保する。

## 3. ブランドカラー

サービス全体の基調色には、落ち着きと視認性を両立するオリーブ系を使用する。オリーブは次のサービス共通UIに使用する。

- メインCTA
- リンク
- フォーカスリング
- 選択状態
- 主要な操作
- カテゴリに依存しない共通UI

黄色系は補助色とし、次の用途に限定する。

- 注意事項
- 小さな強調
- 補助的なアクセント
- カテゴリ識別要素
- アイコンの淡い背景

Primary buttonには、白文字との十分なコントラストを確認した濃いオリーブを使用する。注意表現には、Primary buttonと区別できる淡い黄色系を使用する。

## 4. カテゴリカラー

将来のカテゴリ追加に備え、カテゴリごとに補助色を設定できる構造にする。次は方向性の例であり、正式な色ではない。

| カテゴリ | 補助色の方向性 |
| --- | --- |
| 電車・駅 | 淡いオリーブ、緑系 |
| 飲食店 | オレンジ |
| ホテル | 緑 |
| 買い物 | 紫 |
| 病院・体調不良 | 赤、ピンク |
| 観光施設 | 黄色、ターコイズ |

カテゴリカラーは次の限定的な場所だけに使用する。

- カテゴリアイコン
- カテゴリラベル
- カードの小さなアクセント
- 淡い背景色
- 見出し周辺の装飾

カテゴリごとに次を変更しない。

- メインCTAの色
- リンクの色
- フォーカスリング
- 基本ナビゲーション
- 操作方法
- ページ全体の背景色

カテゴリカラーは操作を示す色ではなく、文字ラベルなどと組み合わせて識別を補助する色として扱う。

## 5. 初期カラートークン

次は初期実装用の候補であり、確定値ではない。

```css
:root {
  --background: #f8f7f0;
  --surface: #ffffff;
  --foreground: #20251c;
  --muted-foreground: #656858;

  --primary: #4f6f3f;
  --primary-hover: #3f5c32;
  --primary-foreground: #ffffff;

  --accent: #f59e0b;
  --accent-soft: #fef3c7;

  --border: #dedfce;
  --focus: #4f6f3f;

  --danger: #dc2626;
  --danger-soft: #fee2e2;
}
```

実際の画面確認後、コントラスト、印象、読みやすさを基準に調整できる。変更時は個別画面へ直接色を追加せず、共通トークンを更新する。

## 6. 背景とサーフェス

- ページ背景は白または非常に薄いグレーとする。
- カードは白を基本とする。
- 強いグラデーションを使用しない。
- 背景全面にカテゴリカラーを使用しない。
- 影は控えめにする。
- カードは境界線または小さな影で背景と区別する。
- 入れ子のカードを増やしすぎない。

## 7. タイポグラフィ

- MVPでは外部フォントを追加せず、システムフォントを使用する。
- UI文言は英語を基本とする。
- 日本語フレーズを画面内で最も大きく表示する。
- ローマ字と英訳は日本語より小さくする。
- 本文はスマートフォンで無理なく読めるサイズにする。
- 小さすぎる補足文字を使用しない。
- 行間を十分に取る。
- 長文を中央揃えにしない。

文字サイズは次を実装時の目安とし、固定値にはしない。

| 用途 | 目安 |
| --- | --- |
| ページ見出し | 28〜36px |
| セクション見出し | 20〜24px |
| カードタイトル | 17〜20px |
| 本文 | 16px以上 |
| 補足 | 14px以上 |
| 駅員に見せる日本語 | 28〜40px以上 |

## 8. 余白とレイアウト

- 375px前後の画面を基準にする。
- PCではコンテンツを中央寄せする。
- 読みやすい最大コンテンツ幅を設定する。具体値は未確定とする。
- 画面左右に十分な余白を持たせる。
- セクション間の余白を統一する。
- カード間に明確な間隔を設ける。
- 主要ボタンの高さは48px以上を目安とする。
- タップ対象同士を近づけすぎない。
- 横スクロールを発生させない。

## 9. 角丸、境界線、影

- カードとボタンの角丸を種類ごとに統一する。
- 角丸を使いすぎて子ども向けの印象にしない。
- 境界線は薄くする。
- 強いドロップシャドウを使用しない。
- Hover時の変化は控えめにする。
- Focus状態はHoverより明確にする。

初期目安は次のとおりで、最終値ではない。

```text
小要素の角丸：8px前後
カードの角丸：12〜16px前後
ボタンの角丸：10〜14px前後
```

## 10. ボタン

| 種類 | 役割と使用条件 |
| --- | --- |
| Primary button | 画面の主目的を進める操作。共通の濃いオリーブ系を使い、1画面に増やしすぎない。 |
| Secondary button | 主操作を補助する操作。Primaryより視覚的な優先度を下げる。 |
| Text link | ページ間移動や補助的な参照に使う。ボタン動作には使わない。 |
| Audio button | 対応する日本語音声を再生する。`Play audio`など状態が分かる文字を表示する。 |
| Show to staff button | 選択した日本語を駅員向けモーダルで表示する。Audio buttonと見分けられる文字と外観にする。 |
| Close button | モーダルを閉じる。常に見つけやすい文字ラベルを表示する。 |

共通ルール:

- ボタンには文字ラベルを付け、アイコンだけの主要操作を作らない。
- Disabled状態を色だけで示さず、操作不能であることが文脈と属性から分かるようにする。
- 十分なタップ領域を確保する。
- カテゴリによってPrimary buttonの色を変えない。
- 危険な操作以外に赤いボタンを使用しない。

## 11. カード

想定するカードは次のとおり。

- カテゴリカード
- 問題カード
- フレーズカード
- 注意事項
- 簡単な案内カード

共通ルール:

- タイトルを明確にする。
- 説明文を長くしすぎない。
- カード全体がリンクの場合は、押せることを視覚的・意味的に示す。
- ボタンを含むカードでは、カード全体をリンクにしない。
- カテゴリカラーは小さなアクセントに限定する。
- 同じ画面内のカード形状を統一する。

## 12. アイコン

- 意味の理解を補助するために使用し、アイコンだけで意味を判断させない。
- 操作アイコンは必ず文字ラベルと併用する。
- 装飾目的のアイコンを増やしすぎない。
- MVPでは新しいアイコンライブラリを追加しない。
- インラインSVG、CSS、Unicodeの使用を優先する。
- 同じ用途のアイコンは線幅とサイズを統一する。

## 13. 状態表現

| 状態 | 表現方針 |
| --- | --- |
| Default | 通常の文字、背景、境界線で基本状態を示す。 |
| Hover | 色や境界線を控えめに変え、レイアウトを動かさない。 |
| Focus | 明確なフォーカスリングを表示し、Hoverより強く示す。 |
| Active | 押下中であることを色、境界線、必要に応じて小さな位置変化で示す。 |
| Disabled | 無効属性に加え、文脈、透明度、文字などを組み合わせる。 |
| Error | 赤系に加えて、具体的な英語メッセージやアイコンを表示する。 |
| Warning | 黄・オレンジ系に加えて、注意文やアイコンを表示する。 |
| Success | 必要な場合だけ使用し、緑だけに依存せずチェックアイコンや文言を併記する。 |

緑は将来ホテルカテゴリに使用する可能性がある。成功状態に使う場合も、カテゴリとの混同を避けるため文字またはアイコンを必ず併用する。

## 14. アクセシビリティ

- セマンティックHTMLを使用する。
- 見出し階層を正しくする。
- キーボードですべての主要操作を利用できるようにする。
- Focus状態を明確にする。
- 文字と背景に十分なコントラストを確保する。
- 色だけで情報を伝えない。
- ボタンには文字ラベルを付ける。
- 装飾ではないアイコンだけを使用する場合は、適切な代替テキストを設定する。
- 音声がなくても日本語、ローマ字、英訳で内容を理解できるようにする。
- モーダルではフォーカスを管理し、閉じた後に起点へ戻す。
- 文字を拡大しても主要操作を利用でき、横スクロールが発生しないようにする。

## 15. 写真、イラスト、アニメーション

MVPでは次の方針とする。

- 写真を使用しない。
- 大きなイラストを使用しない。
- 日本を連想させる装飾を多用しない。
- 路線図や鉄道記号をブランドの中心にしない。
- JavaScriptアニメーションを使用しない。
- CSSアニメーションも必要最小限にする。
- 操作の妨げになる動きを入れない。

## 16. 避けるデザイン

- 電車専用サービスに見えるデザイン
- 観光情報サイトのような写真中心のデザイン
- 日本語教材のような学習感の強いデザイン
- 色を多用したデザイン
- 画面ごとに異なるボタン色
- カテゴリごとに異なる操作方法
- 黄色やオレンジの上にコントラスト不足の白文字
- 過度なグラデーション
- 強い影
- 小さい文字
- 小さいタップ領域
- アイコンだけのナビゲーション
- 不要な固定ヘッダーや固定フッター

## 17. MVPでの適用範囲

初回MVPでは次へ適用する。

- トップページ
- 問題一覧ページ
- 問題詳細ページ
- フレーズカード
- 音声再生ボタン
- 駅員に見せるモーダル

初期デザイン確認では、まず次の2画面だけを実装対象とする。

1. トップページ
2. 問題一覧ページ

この2画面で色、文字、余白、カード、ボタン、モバイル表示を確認してから、問題詳細、フレーズカード、音声操作、モーダルへ展開する。

## 18. 未確定事項

- 正式なサービス名
- ロゴ
- 最終的なカラーコード
- 各カテゴリの正式な色
- アイコンの正式なデザイン
- 最大コンテンツ幅
- 角丸の最終値
- 音声再生中の表示
- ダークモードの必要性

ダークモードは必要性自体が未確定だが、MVP対象外とする。初期カラートークンや数値目安は実装・実機確認後に調整でき、現時点では確定値として扱わない。
